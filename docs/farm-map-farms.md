# 中国地图选点 · 农场 · 地块

> 层级：**区县 → 农场 → 地块 → 作物**
> 区县是地图上的最小可选单位，决定农业气候区；农场是玩家在区县里的落脚点；地块是真正种东西的单位。

## 一、数据来源与处理

| 项 | 说明 |
|---|---|
| 边界数据 | 阿里 DataV GeoAtlas（`geo.datav.aliyun.com/areas_v3`），2026-10 抓取 |
| 覆盖 | **2875 个县级单位**，34 个省级行政区（含台港澳） |
| 文件 | `frontend-learning/public/geo/cn.json`（省级，440KB）+ `p{省adcode}.json`（该省全部区县，合计 4.9MB） |
| 索引 | `spring-boot-learning/src/main/resources/farm/districts.json`（adcode/名称/省/市/经纬度） |
| 生成脚本 | `scripts/geo/build_geo.py`（带磁盘缓存，幂等重跑） |

**简化策略**：Douglas-Peucker，容差 0.006°（约 600m），坐标保留 4 位小数。区县显示足够，单省 100–300KB。

**三个数据坑**（已修，重跑注意）：

1. 九段线等辅助要素的 adcode 是 `100000_JD` 这类字符串，必须先判类型再转 int；
2. 不设区的市（中山、儋州、嘉峪关、新疆兵团各市）**没有下级边界**，接口返 404 —— 它自己就是县级单位，要收回；
3. **403 是限流不是不存在**。第一版把 403 也当成"无下级"缓存成空表，导致全国少 990 个区县且永远补不回来。现在只对 404 落 `_missing.json`，其余退避重试。

## 二、区县 → 农业区 → 主栽作物

`DistrictCropService` 两层叠加：

1. **省域主栽先验**：按省级归属给候选与优先级（东北=玉米/大豆/水稻，黄淮海=冬小麦/夏玉米，华南=双季稻），两处按纬度破例（东北北纬 45.5° 以北大豆优先；河南信阳是稻区）；
2. **本地气候可行性**：用 `SuitabilityEngine` 对该区县所属农业区做十年回放，给每个候选作物的适种等级。

**口径必须写清**：这不是统计年鉴的县级播种面积，是**模型推算**。UI 上明确标注「气候档案为模型推算，非气象业务数据」。

排序策略：**先验优先**，只有当先验首位已经「风险较高/不推荐」时才让位给等级更好的作物。
否则吉林、辽宁的玉米会输给大豆（模型给玉米 L1、大豆 L0），与实际主栽完全相反 —— 先验回答"当地种什么"，等级回答"种得好不好"。

当前各区域结论（实测）：

| 区域 | 主栽分布 |
|---|---|
| 黑龙江 | 大豆 101 / 玉米 21（北纬 45.5° 分界） |
| 吉林 | 玉米 57 / 大豆 3 |
| 辽宁 | 玉米 100 |
| 河南 | 冬小麦 147 / 水稻 10（信阳） |
| 江西 | 水稻 100 |

性能：等级只与 (气候区, 作物, 年份) 有关，全国 2875 个区县实际只有 4×4=16 种组合，算一次缓存；一个省上百个区县的概览接口是毫秒级。

## 五、地图实现

### 1. 为什么自绘 SVG 而不用图表库

- echarts `geo` + `series.geoIndex`：series 的逐项 `itemStyle` 不生效，整省一个色；
  geo 的 areaColor 设透明又变全黑；
- map series 上挂 `markPoint`：数据进去了但不出图；
- `layoutCenter/layoutSize` 与 `roam` 同用：**绘制变换与点击命中不一致**，点江西命中新疆（偏移 200px+）。这是最终放弃 echarts 的直接原因。

SVG 方案：path 由浏览器渲染，**命中判定就是路径本身**，不存在两套坐标；农场标记与区划共用同一套投影，位置天然对齐。

### 2. 投影：Web Mercator（**全局固定基准**）

早期用等距圆柱（经度乘 `cos(中纬度)`、纬度再乘 0.86）。改墨卡托有两个理由：

1. **和开放底图对齐**。任何标准栅格瓦片（天地图 / 高德 / OSM）都是 EPSG:3857，
   矢量区划与卫星影像落在同一坐标系，不需要维护两套变换；
2. 缩放锚点、标记定位、命中判定全部共用一套世界坐标，不会「越缩越飘」。

```js
worldX(lng) = (lng + 180) / 360
worldY(lat) = 0.5 - ln(tan(π/4 + lat·π/360)) / 2π
```

投影后按 bbox 归一到 1000 宽的局部坐标：`x = (worldX - wx0) · K`，`K = 1000 / (wx1 - wx0)`。
中国范围 18°–54°，墨卡托的纬度拉伸约 1.7 倍，在可接受范围内。

> **关键约束：K 是全局常量，不随当前显示哪一层而变。**
>
> 旧实现每次切换「全国视图 / 省视图」都用那批数据的 bbox 重算 K，
> 于是省视图和全国视图成了**两套坐标系**，缩放只能放大陆省界 —— 滚轮永远看不到区县级。
> 现在全国、省、区县共用同一个 K：
>
> - 全国适配 = zoom 1；
> - zoom N = 视野宽度变成 1/N，坐标永远连续；
> - 区县图层作为独立图层叠加在省图层上，边界严丝合缝。
>
> 基准取陆域主体（73°–136°E，18°–54°N）。南海诸岛在 3.8°N，
> 算进基准 bbox 会把地图纵向拉长近一半、手感全废；
> 但**平移边界按世界范围夹**（`PROJ.world`），保证岛礁平移得到、不会被裁掉。

### 3. 缩放与平移

| 操作 | 实现 |
|---|---|
| 滚轮 | 以光标为锚点，`pan += vbW·(1−1/f)·(t−0.5)`，t 是光标在可视区的相对位置 |
| 拖拽 | `pointerdown/move/up`；位移超过 4px 才算拖拽，避免吞掉点击 |
| **双指捏合** | 移动端：跟踪活跃触点，两指距离比值缩放，以两指中点为锚点（与滚轮同一套锚点逻辑） |
| 双击 | 放大 1.9 倍（Shift 双击缩小）；**双击省/区县 = 直接聚焦到它** |
| 按钮 | ＋ / − / ⤢ 复位，右下角常驻 |
| 范围 | 1×（整图，视野 ~67°）– 40×（视野 ~1.7°，已能看清一个县内部） |

**viewBox 跟容器比例走**：`fit` 在 base 尺寸外按容器宽高比扩展，使 viewBox 比例恒等于容器比例，
`preserveAspectRatio` 不会产生留白，缩放锚点公式才成立（有留白时 t 会落在 0–1 之外）。
`pan` 的 clamp 上限是 `worldW/2 − viewW/2`，拖不出图外。

几个刻意的取舍：

- **标记半径除 zoom**（`r = 5.5 / zoom`），描边用 `vector-effect="non-scaling-stroke"`，
  放大后标记不会变成大圆斑；
- **经纬网密度跟着视野走**（0.25° 一档往上选，目标是一屏 3–9 条），
  固定 10° 在全国视图只剩几条、放大后一条都没有。网格必须画在陆地**之上**，否则被填充盖住；
- **海面光晕用 `userSpaceOnUse`**。跟着视口走（objectBoundingBox）时，放大到 5 倍整个视口只剩渐变最外圈，黑得像没加载；
- **省界常驻底图**。区县层叠在省界之上，玩家放大后仍能看出「这个县属于哪个省」，不会迷失在全国色块里。

### 4. 区县级：按视野自动加载（**不用点击进去**）

区县不再是「点省 → 切视图」的第二级，而是**与省界并列的图层**，随缩放自动出现：

| 视野跨度 | 层级 | 行为 |
|---|---|---|
| > 26° | 全国 | 只有省界 |
| 3.5° – 26° | 省级 | 加载视野内省份的区县层 + 显示省名标注 |
| < 3.5° | 区县级 | 显示区县名标注 |

**可见省份的判定**：先用 bbox 粗筛，再用「视野中心 + 5×5 网格采样」做点在多边形判定。
纯 bbox 不够 —— 内蒙古的 bbox 覆盖整个华北，会把十几个省都算进来。
网格采样用射线法，并处理内环挖洞。

**加载时机**：视野变化后 180ms 防抖，命中省份并发拉两路数据 ——
边界来自静态 `p{adcode}.json`（离线、无鉴权），作物画像来自后端
`/map/districts`（服务端权威的「这个县适合种什么」，前端不能自己算）。
结果缓存在 `districtLayers` / `distApiCache`，来回平移不重复请求。

**点选行为**：

- **点省** = 镜头推到该省 + 钉住该省的区县层（即使镜头还没推近，区县也先显示出来）；
- **点区县** = 右侧出区县详情（气候区、主栽作物与物候、14 种作物评级、建场入口），
  **不再需要「进入省视图」这一步**；
- **双击省/区县** = 聚焦到它（点省是聚焦省，点区县直接聚焦到县）。

**右侧面板范围 = 视野中心所在省**，随镜头自动变化。
地图位置和右侧内容永远一致，玩家不需要「点一下才知道这里有什么」。
镜头移到境外（海里）则回到全国概览。

### 5. 标注

- **省名**：视野跨度 3.5°–26° 时显示，位置取省 bbox 中心（简化后的边界不保证有真质心，bbox 中心更稳定）；
- **区县名**：视野跨度 < 3.5° 时显示，位置取区县 bbox 中心；跨度 < 0.5° 的区县跳过（名字会盖住相邻县）。

字号随缩放反向缩放（SVG 里的字号不随 viewBox 缩放），保证名字大小恒定；
白字 + 深色描边（`paint-order: stroke`），压在任何底图上都能看清。

### 6. 天地图接入（后端代理架构）

#### 6.1 为什么是后端代理

天地图的 key 分「浏览器端」和「服务端」两种，**权限类型互斥**：

| key 类型 | 服务端调用 | 浏览器调用 |
|---|---|---|
| 浏览器端 `01c5…` | ❌ `403 / 301012 Key权限类型为:浏览器端，请使用浏览器访问！` | ✅ |
| 服务端 `bfed…` | ✅ | ❌ `403 / 301013 Key权限类型为:服务器端，请使用服务器端访问！` |

选**后端代理**：服务端 key 写进 `application.yml`（走环境变量 `TIANDITU_SERVER_KEY`），浏览器永远拿不到 key。
代价是多一跳网络；收益是 key 不进 DevTools、不进打包产物，还能加缓存与限流。

> **踩坑**：天地图按 **User-Agent** 判权限类型。服务端请求带 `Mozilla/5.0` 会被拒（`301013`），
> 必须用非浏览器形态 UA（实测 `SpringBootTianDiTuProxy/1.0` 通过，不设 UA 也通过）。
> 「带浏览器 UA 防 WAF」在这里是**反的**。

#### 6.2 后端接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/map/tianditu/status` | 自检：是否启用、是否配了 key、允许的图层列表（**不含 key 内容**） |
| GET | `/api/map/tianditu/tile/{layerType}/{z}/{x}/{y}` | 瓦片代理，直接返回图片字节（不是 Result 包装），`Cache-Control: public, max-age=86400` |
| GET | `/api/map/tianditu/search?keyword=&level=&mapBound=&start=&count=` | 地名搜索（v2/search），返回天地图原始 JSON |
| GET | `/api/map/tianditu/geocode?keyword=&level=` | 地址编码（地名 → 坐标） |
| GET | `/api/map/tianditu/reverse?lon=&lat=` | 逆地理编码（坐标 → 地址） |

这些端点**不要求登录**（放进 `JwtAuthFilter.isGuestReadable` 而非 `shouldNotFilter`）——
瓦片由 `<img>` 加载根本不会带 Authorization 头，走鉴权地图直接空白；
而放在 `isGuestReadable` 里能保证「带 token 的请求仍能解析出 userId」，将来做「我的农场在地图高亮」不用改架构。

#### 6.3 图层体系

| 用途 | 图层 | 类型 | 配对注记 |
|---|---|---|---|
| 矢量底图 | `vec_w` | png | `cva_w` |
| 卫星影像 | `img_w` | jpg | `cia_w` |
| 地形晕渲 | `ter_w` | jpg | `cta_w` |

- **底图与注记分开两层**：矢量底图本身不含地名，注记是独立的透明瓦片，单独开关；
- 天地图 z 范围 **3–18**（超出返回空白瓦片）；
- `LAYER` 参数要**去掉 `_w`**（`/img_w/wmts` 配 `LAYER=img`；传 `LAYER=img_w` 虽返 200 但内容是空白占位瓦片）；
- **content-type 必须透传**：影像/地形是 `image/jpg`，矢量/注记是 `image/png`，写死 png 会让浏览器因 `nosniff` 拒绝渲染 JPEG；
- 底图与注记层**共用同一套 z/x/y 瓦片网格**，只是图层名不同。

#### 6.4 前端交互

| 功能 | 实现 |
|---|---|
| 图层切换器 | 工具条弹出面板：3 底图 + 4 注记选项；切换底图时自动配对默认注记，用户可再手动覆盖 |
| 地名搜索 | **双源**：本地 2875 县检索（快、含 adcode 能直接定位区县）+ 天地图 POI（补充），防抖 300ms，`mapBound` 传当前视野；天地图不可用时静默降级到本地 |
| 逆地理编码 | 点地图**空隙处**（不命中省/区县 path）→ 弹地址气泡（省·市·县 + 完整地址 + 附近 POI + 坐标） |
| 距离测量 | 测距模式点 2 个点 → Haversine 直线距离，橙色 |
| 面积测算 | 测面模式点 ≥3 个点 → 双击结束 → Shoelace 面积，青色 |

搜索结果按 `resultType` 分支：`1` = POI 列表（`pois[]`）、`2` = 按城市统计（`statistics.priorityCitys`）、`3` = 行政区划（`area`）。

> **天地图的四个 quirks**：
> 1. `v2/search` **必须带 `mapBound`**，否则 `400 缺少参数：mapBound`；
> 2. 鉴权参数是 `tk` 不是 `key`（用 `key` 报 `308010`）；
> 3. 地址编码走 `ds=`、逆地理编码走 `postStr=`，**两个通道不能混用**（用错会得到 `lon/lat 参数未填写` 这种毫不相关的报错）；
> 4. 点边境/境外时 `formatted_address` **可能为空串**，但 `addressComponent` 里还有 poi/镇名 —— 前端要降级拼一个，不能整个丢弃气泡。

#### 6.5 底图与矢量层的叠加规则（fill 透明度）

省界 / 区县色块是**不透明的实色**，直接压在卫星或地形底图上会把影像整片盖住
（卫星底图只剩国界外露出影像）。所以 fill 必须分两套：

| 底图 | 省界 fill | 区县 fill |
|---|---|---|
| 矢量（`vec_w`） | `rgba(68, 98, 68, 0.95)`（实色） | `rgb(...)` 实色作物分区 |
| 卫星 / 地形 | `rgba(30, 52, 38, 0.14)`（有农场的省 `rgba(140, 205, 96, 0.26)`） | `rgba(..., 0.26)`（有农场 0.42） |

两个实现要点：

1. **CSS 的 `fill-opacity` 覆盖不掉 inline 绑定的 `fill`** —— 透明度只能在 JS 里算成 `rgba()`。
   同理 CSS 里的 `.wm-prov { fill-opacity: 0.96 }` 必须删掉：省界与区县是两套配色，
   同一规则没法区分，叠加后半透明会被再乘一次，影像透不出来。
2. **区县 fill 不能烘焙进 `districtLayers` 缓存** —— 缓存是异步加载时算的，而底图可随时切换，
   烘焙后切底图不会重算。缓存只存 `baseColor` + `shadeK`，在渲染 computed 里按当前
   `baseLayer` 现算 fill（`shade()` 出实色、`shadeA()` 出带 alpha 的 rgba）。

> **验收时的误报**：SVG `<image>` **没有 `naturalWidth` 属性**，用 `i.complete && i.naturalWidth === 0`
> 判破损在 SVG 上恒为真，会误报「全部瓦片损坏」。判 SVG 图片是否真的加载失败，
> 要用「后端返回字节大小 + 视口网格采样覆盖率（40×24）」两招。
> 卫星图上「江苏沿海斜边色块」看着像瓦片缺口，实际是淤泥质海岸线的真实地貌。

#### 6.5 为什么不是高德/腾讯

它们用 GCJ-02，我们的区县中心与边界是 WGS84/CGCS2000，直接叠会有 300–700m 的系统性偏移（在 4× 放大下就是一整条街）。天地图是官方 CGCS2000，与 WGS84 差 <1m，不需要纠偏。

**为什么默认仍是矢量**：区县边界比 z≤10 的瓦片更清楚，而且主栽作物着色只有矢量能表达。

### 7. 首屏与右侧面板

进入「稼穑」**先落地地图概览**（`worldMapOpen = ref(true)`），再下地。右侧面板四种形态：

| 选中状态 | 面板内容 |
|---|---|
| 未选中（全国） | **全部农场概览**：农场/地块/生长中/可收割四个数，作物分布胶囊，农场卡片（含地块状态小方块），未归属农场的地块 |
| 视野中心在省 | **该省概览**：同上，scope 收窄到该省；底部提示「另有 N 块田未归属农场」 |
| 选中区县 | 区县详情：气候区、主栽作物与物候、14 种作物评级、建场/进农场 |
| 选中农场 | 农场详情：地块表、该县适合种什么、进入农场 |

面板数据来自 `/board` 一次聚合（`plotSummaries` 每块地跑一次 SimEngine，100 块地几十毫秒），
按 `adcode` 前端过滤出省域范围，不额外请求。

**未归属地块**必须单列：v1 时期开的田 `farm_id` 是 null，如果概览只统计「农场下的地块」，
玩家会看到「1 块地」而实际有 11 块。这类地块单独成区，点击直接进那块田。

**点农场先加载区县层再定位**：`focusFarm()` 先 `ensureProvince()` 加载所在省的区县层，
再 `flyTo(18×)`——放大后画面里得是有边界的区县，而不是一整片省域色块。

## 六、已知局限

1. **同省同色**：区县主栽由「省先验 + 农业区」决定，同一省内多数区县相同（江西 100 个县全水稻）。真实县级播种面积数据没有可靠公开机读源，这是数据粒度问题，不是渲染问题；靠 ±13% 亮度微扰 + 深色区县界线缓解；
2. **没有市一级**：地图只有全国（省）/ 省（区县）两级。GeoJSON 有市级数据，但再加一层会让「点三下才能建农场」的路径变长，暂时不做；
3. 只有 4 个气候档案，新疆/甘肃等干旱区被归到黄淮海，棉花等作物不在作物库；
4. 台湾无下级边界数据，按省级单位作为最小可选点；
5. 全国视图不裁南海诸岛（领土完整优先），但**基准 bbox 不含 3.8°N 以下的岛礁**，避免整张地图纵向拉长；平移可到达岛礁；
6. `farm.demo-mode=true` 的演示接口（`/advance`、`/weather/mock`）上线前仍需关闭。
7. **天地图按 tk 限流**：实测会返回 `429`。瓦片走浏览器缓存（`max-age=86400`）能挡掉大部分重复请求，
   但快速拖动地图仍可能触发上游限流。生产部署建议加瓦片二级缓存或申请更高配额。
8. **代理层瓦片不缓存**（只靠浏览器 `max-age`），后端每次都会打上游；这是刻意的 ——
   瓦片是不可变资源，缓存收益低而内存成本高；搜索/地理编码结果才值得缓存（数据几乎不变）。
