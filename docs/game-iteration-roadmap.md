### 2.4 排行榜：✅ 后端已通（🔴 推翻旧结论）

**旧结论**（记忆里）：「农场排行榜后端早就接好了，缺的只是前端 UI」——
**实测推翻**：前端 UI **早就存在**（`GameFarm.vue:551` 有 `el-tab-pane` 排行榜页签，
懒加载 `getLeaderboard('farm', 20)`）。

真正的情况是**端到端全通且有真实数据**：

```
GET /api/games/farm/leaderboard → 200
  rank 1: admin / tupengfamily / 最高分 2598 / 13 局
  rank 2: user  / user         / 最高分 233  / 1 局

> 📌 **因此「做排行榜」不是下一步** —— 它已经能用了。
> 唯一可补的是：**口径说明**（分数是 kg/亩×折价，不是元，UI 底部必须写清）。

### 2.5 🔴 关键缺口：归因明细被丢弃

后端 `extra_json` 里存了 20+ 个归因字段（为什么减产、用了多少肥、农残是否违规、净收益），
但 **`GameHistory.vue` 里一个字段都没展示**（grep `extra|crop|revenue|net` 零命中）。

**这是当前最高性价比的缺口** —— 数据已经在库里躺着，只差一张 UI。

### 2.6 🔴 农场与学习平台：完全隔离

| 维度 | 实测 |
|---|---|
| 货币 | `t_farm_wallet` 独立闭环，初始余额固定，**与平台学币无任何联通** |
| 任务 | `t_todo` 表存在但 **0 行**，农场未接入 |
| 引导 | `OnboardingController` 里 **grep farm 零命中** |
| 课程 | `GameFarm.vue` 里 **grep course/积分/学币 零命中** |

> 这个平台的主张是「通用学习平台」，稼穑是它唯一的「农业模拟」品类。
> **不打通平台能力，稼穑就只是一个挂在学习平台上的独立小游戏。**

### 2.7 🔴 真实数据量极小 → 核心循环未被验证

```

5+ 步动作 + 数十天推进。当前数据说明：**要么玩家没玩进去，要么引导缺失导致中途放弃。**

## 三、迭代方向建议（按 ROI 排序）

### 🥇 P0 — 归因明细可视化（投入最小，回报最高）

**做什么**：游戏历史页的 farm 分类下，展示每局的**归因链**：
「这季为什么只有 613 分」→ 减产 12%（青枯病 8% + 渍害 4%）→ 用了 3 次药 → 农残超标 → 净收益 ¥2,340

**为什么先做**：
- 数据**已经在 `extra_json` 里**（14 条 farm 记录全带完整归因），零后端改动
- 直接补上「玩家不知道为什么」的缺口 —— 这是模拟经营游戏的**核心反馈**
- 复用 2048 已有的 `el-tab-pane` 排行榜范式，不引入新技术

**验收**：游戏历史页 farm 标签能展开看单局归因表；归因数字与 `/state` 引擎指纹一致。

### 🥈 P1 — 农场接入平台任务/引导（把「小游戏」变成「学习平台的一部分」）

**做什么**：
1. `t_todo` 预置农场任务链：播种第一块地 → 完成一次追肥 → 收完第一季 → 解锁图鉴
2. `OnboardingController` 加农场分支（首次进农场的 5 步引导）
3. 农场货币与平台积分**单向打通**（农场收益 → 平台积分，不反向）

**为什么**：
- §2.7 的数据（1.3 动作/地块）指向的就是**引导缺失**
- 任务系统是平台已有能力（`t_todo` 表已在），只是没接农场 —— 边际成本极低
- 让稼穑成为平台的「可持续日活」入口，而不是「逛到才玩」

**验收**：新用户首次进农场看到引导；完成任务发平台积分；`t_todo` 出现农场任务行。

### 🥉 P2 — 前端上帝类拆分：`FarmWorldMap.vue` 6712 → 拆包

**做什么**（对齐后端 S4–S7 的做法）：
- `FarmWorldMap.vue` → `farm/map/` 目录：地图渲染 / 区县面板 / 农场列表 / 作物分布 / 建场表单
- 每拆一块跑一遍 375×812 + 1600 双视口回归

**为什么现在做**：
- 它是**全项目最大单文件**，改任何地图逻辑都要读 6000+ 行
- 后端 S1–S3 已经证明了「ArchUnit + 分步抽取 + 每步测试绿」这条路走得通
- 前端可以用同样的「白名单豁免 + 规模守门」建 ESLint 规则

**验收**：`FarmWorldMap.vue` < 1500 行；新增 ESLint 规则锁住单文件上限；双视口回归无回归。

### P4 — 后端 S4–S7（继续拆 `FarmPlayService`）

**做什么**：按架构决策文档既定顺序 S4 `FarmSuitabilityService` → S5 `FarmActionService`+`FarmInputService`
→ S6 `SeasonAdvanceService`（事务最重，最后动）→ S7 `plot`/`season` 子包。

**为什么**：3340 行的上帝类仍是最大架构债；但**它不阻塞玩法迭代**，应排在 P0–P3 之后。

### P5 — 内容扩展（低优先级）

真实数据量小的时候加作物只会加深「没人玩」的坑。**先修闭环，再加内容。**

## 四、明确**不该做**的方向

| 方向 | 为什么不做 |
|---|---|
| 🔴 **做农场排行榜** | **已经全通了**（§2.4，实测 200 + 真实数据）。UI 也已有。只需补口径说明。 |
| 🔴 **加新作物 / 新农资** | 22 种 + 51 项已饱和；真实使用数据才 23 地块（§2.7），**内容不是瓶颈** |
| 🔴 **拆微服务** | 已定案不拆（`architecture-decision-monolith-vs-microservices.md`）；当前规模远未到阈值 |
| **加中间件（MQ/Redis）** | 无异步需求、无跨进程通信、无分布式锁需求 |
| **给农场做好友/交易/集市** | 零社交代码，但**得先有足够玩家**；现在做是空中楼阁 |

---

## 五、给决策者的三个问题

1. **稼穑的定位是「学习平台里的一个游戏」还是「学习平台的农业学科模块」？**
   → 决定 P1（打通平台）是核心功能还是锦上添花
2. **玩家预期的单局时长是多少？**（当前一个种植周期 = 数周游戏日 + 数十次点击）
   → 决定要不要做「时间加速 / 赛季压缩」
3. **归因明细是给谁看的？**（新手教学 / 高手优化 / 数据分析）
   → 决定 P0 的信息层级与交互深度
