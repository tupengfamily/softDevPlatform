## 一、结论摘要

共发现 **14 个问题**，其中：

| 级别 | 数量 | 说明 |
|---|---|---|
| 🔴 严重（机制与文案/引导相反，或数值完全失效） | 4 | 已全部修复并有回归测试 |

**最重要的三个发现：**

1. **预防性打药的实际收益为 0** —— 而 UI 文案恰恰写着「显症前预防效果最好」，机制与引导完全相反。
2. **稻瘟病等三种主要水稻病害在连续阴雨下永远不会发生** —— 湿度适宜度的方向算反了，「刚好达到病害需求下限」被当成 0。这三个 bug 互相掩盖，单独看任何一个都像"正常参数"。
3. **玩家做对了操作反而被判"漏工序"** —— 产量被凭空扣 6%，玩家越认真越吃亏。

## 二、严重问题（🔴，已修复）

### 1. 预防性打药完全失效 —— 保护期挂在"已发生实例"上

**位置**：`engine/PestEngine.java`（`simulate` 施药块 + `protectedNow`）

**现象**：保护期 `protectUntil` 原本是 `MutablePest` 的字段，而 `MutablePest` 只在病害**已经发生**时才创建。于是：

```
显症前打药 → active 里没有该病虫 → protectedNow() 遍历不到 → 菌源不打折 → 病害照常发生
```

**复现**：任意季节，在稻瘟病显症前打一次三环唑，与完全不打药，最终产量损失**完全相同**。

**根因**：保护期是"药剂在田里的残留效力"，与靶标是否已发病无关；而原实现把它建模成了"已发病个体的治疗状态"。

**修法**：改为维护「靶标 → 保护截止日」表，由施药记录直接写入，与实例存在与否解耦。保护期内该靶标初发概率 ×0.25。

**验证**（探针实测，60 seed 聚合）：

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 不打药 | 117 次发病 | 117 |
| 对症打药（显症前） | 117 次 | **114** ↓ |
| 打错药 | 117 次 | 117（不产生保护期）✓ |

### 2. 湿度适宜度方向算反 —— 连续阴雨下病害永不发生

**位置**：`engine/PestEngine.java` → `envSuitability()`

**现象**：
```java
double fh = Math.max(0, Math.min(1, (rh - cfg.humidityMin()) / 15.0));
```
「湿度**刚好等于**病害需求下限」时 `fh = 0`。而 `humidityProxy()` 只有 68/82/90/95 四档，`humidityMin=90` 的三种主要水稻病害（稻瘟病 / 纹枯病 / 白叶枯病）在日降水 5–20mm（rh=90）时适宜度**恒为 0**。

**复现**（探针实测，修复前）：

| 日降水 | 湿度代理 | blast 发生次数（120 seed） |
|---|---|---|
| 12mm | 90 | **0** |
| 25mm | 95 | 71 |

**现实反直觉**：稻瘟病恰恰在连续阴雨（日降 5–15mm）时最重，而这正是它被设成"不发生"的区间。

**修法**：与温度项对齐 —— 达到需求下限即"需求已满足"（适宜度 1），低于下限时按差值线性衰减：
```java
double fh = rh >= cfg.humidityMin() ? 1.0
        : Math.max(0, 1 - (cfg.humidityMin() - rh) / 15.0);
```

**验证**：日降水 12mm 下 blast 发生次数从 **0 → 117/120**。

### 3. 做对了操作反而被判"漏工序"

**位置**：`farm/OpChain.java` → `build()`

**现象**：
```java
} else if (done && (!d.repeatable() || at >= d.from())) {
    st = Status.DONE;
```
非重复工序也要求"做的时候 DVS ≥ 窗口下界"。玩家在 DVS 0.15 做了分蘖肥（窗口 0.16–0.34），明明做对了，却因 `at(0.15) < from(0.16)` 落进 `MISSED` 分支 → `FarmPlayService.yields()` 扣 0.94（**产量凭空少 6%**）。

**修法**：「已做」就是 DONE。做得早/做得晚应该由 `qualityOf()` 的时机质量折扣体现（那是它该待的地方），而不是把"已做"改写成"漏做"。

---

### 4. 换季后播种日与演示时钟脱钩 → 本季数据异常

**位置**：`farm/FarmPlayService.java` → `harvest()` / `restart()` / `createField()`

**现象**：`demoOffsetDays` 被 `Math.min(..., MAX_DEMO_OFFSET_DAYS=3650)` 截断，但 `sowDate` 无条件设为 `nextSow`。偏移触顶后：
```
effectiveToday() = 今天 + 截断后的偏移  <  sowDate
→ 回放天数为负 → 本季数据异常
```

**修法**：`sowDate` 由演示偏移反推，两者永远自洽。偏移触顶时新季播种日 = 截断后的 `effectiveToday()`。

## 三、中等问题（🟠，已修复）

### 5. 旧存档的打药记录被判成"打错药"，药效只剩 5%

**位置**：`FarmPlayService.pests()` → `PestEngine.simulate(..., legacyAllTargets=false, ...)`

**现象**：`legacyAllTargets` 恒传 `false`，而旧数据（无 `itemId`）的 `targets` 是空集 → `matches()` 恒 false → 对症药被当成打错药，防效 5%。玩家在旧存档里补打一次药几乎白花钱。

**修法**：按本季是否出现旧记录动态决定 `anyLegacy`。

### 6. 药害剂量不授予保护期

**位置**：`engine/PestEngine.java` 施药块

**现象**：`doseFactor` 在 >1.5 倍推荐量后返回负数 → `power` 被 clamp 到 0（药效全无），但保护期照发。多打药 = 白拿保护期，药害反而成净收益。

**修法**：`power <= 0` 时不写保护期。

### 7. 施肥工序类型用水稻的硬编码阈值，误伤其它作物

**位置**：`FarmPlayService.applyInput()`

**现象**：`dvs < 0.10 / 0.34 / 0.55` 是水稻的窗口。小麦返青肥是 0.42–0.52、玉米苗期肥 0.15–0.30、瓜类整枝 0.18–0.45。小麦在 DVS 0.45 追返青肥 → 被判成「穗肥」→ 工序链匹配不上 → 漏工序惩罚误触发，产量凭空少 6%。

**修法**：新增 `OpChain.fertStepFor(dvs, cropId)`，按当前作物的工序定义取"当前 DVS 落在窗口内、优先级最高"的那道。

### 8. 积温不足 0.55–1.0 区间无任何惩罚

**位置**：`engine/SimEngine.java` → `maturityRatio`

**现象**：只在 `maturityRatio < 0.55` 时把 grains 归零，0.55–1.0 之间完全没惩罚。「只完成 56% 积温」和「积温刚好够」拿到几乎一样的产量。

**修法**：对粒重与粒数做连续惩罚（完成度 55% → 惩罚 0.45，满分 → 0），与 `fillFactor` 分工：`fillFactor` 管"按 DVS 走到哪一步"，这里管"积温够不够"。

### 9. PHI 违规只上报最后一条，而非最严重的一条

**位置**：`FarmPlayService.harvest()`

**现象**：每次违规都覆盖上一条。玩家打 3 次药，第一次差 20 天、最后一次只差 2 天，提示却说"差 2 天" → 玩家误判风险。

**修法**：保留 `phiDaysShort` 最大的一条，并新增 `phiViolations` 计数。

### 10. 剂量上限与药害阈值脱节

**位置**：`FarmPlayService.applyInput()`

**现象**：上限是 `doseMax × 2`，药害阈值是 `doseOpt × 1.5` → 玩家可以合法施用 1.5~2 倍推荐量的**药害剂量**：药效为 0，钱照花，药害照算。

**修法**：硬上限对齐到 `doseOpt × 1.5`，超过直接拒绝（文案说明原因）。

## 四、轻微问题（🟡）

### 11. `validateActionWindow()` 里 FERTILIZE / PESTICIDE 是死代码 ✅已修

`performAction()` 入口已把这两种类型连同 BASE/TILLER/PANICLE_FERT 一起拦掉（"请通过「农资」选择具体药剂/肥料"），但窗口校验里仍留着两套互相矛盾的配置。留着会误导后续维护。**已移除**。

### 12. 产量被 `yieldCap` 静默截断 ✅已修

`Math.min(eyRaw, yieldCap)` 无任何提示，归因表里查不到原因。**已修**：新增 `yieldRaw` / `yieldCap` / `yieldCapped` 字段 + 前端弹窗说明。

### 13. 病害发生率过高（100% 必然发生）✅已修

湿度 bug 修好后 `pEnv` 恒为 1，`p = inoculum`（0.045–0.070）被 clamp 到 0.06，敏感期 47 天里日均 6% ≈ **必然发生**（实测 60/60 全中）。

**修法**：日初发概率上限 0.06 → **0.02**。敏感期累积发生率从 ~100% 降到 **65.5%**（探针实测 131/200），且预防性打药仍有真实经济价值（把 65.5% 压到更低）。

### 14. `SimEngine.java:361` 三元两侧相同 ⏳待办（无害）

```java
int growthDays = matureDate != null ? k : k;
```
两侧完全相同。`growthDays` 的语义是"本季生长天数"，`matureDate != null` 时 `k` 已经是成熟当天的下标，两侧本就相同——**不是 bug，但代码意图不明**。建议改为 `int growthDays = k;` 或补注释说明。未改动，避免影响回归口径。

## 七、遗留观察（未改，供后续决策）

1. **`ClimateModel.aatDay()` 硬编码 10℃/30℃**，与 `SimEngine.aatDay(tmean, crop)` 的按作物口径不同。仅影响适区评级的 F1 **展示值与缺口折算**，不影响定级（定级走 `replayOne()` 按作物口径真实回放）。若要彻底统一，应把 `aatSupply` 改成按作物参数计算。
2. **`DisasterEngine` 的 RICE_TOLERANCE_* 常量对园艺作物也生效**（冻害 1.2、涝 0.4 是水稻值），园艺作物的灾害损失可能偏重。当前病害与灾害损失有上限保护（0.6），影响可控。
3. **`OpChain` 的 `HARVEST` 窗口 0.92–1.30 与 `FarmPlayService.HARVEST_DVS = 0.92` 一致**，但 `SuitabilityEngine` 的产量带用 `Y_REF`（虽已改用 `crop.yieldRef()`，`Y_REF` 常量本身已无引用）。
